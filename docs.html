Overview

What the API does, how it is versioned, and the conventions used throughout this reference.

The EyeGod API exposes the same intelligence graph that powers the web dashboard. Every request is a single HTTP call that returns JSON — no SDK required, no stateful sessions, no per-source credentials to manage.

API versions

1.1Choosing a version

Both versions read from the same database and share authentication, credits, rate limits and error codes. They differ only in request shape.

VersionStyleBest forStatus
v2REST — value in the URL path, plus optional POST bodyNew integrations, browser and no-code tools, batch jobs, webhooksRecommended
v1RPC — single POST with a JSON bodyExisting clients already in productionSupported
Migrating from v1?v2 accepts the exact v1 body shape at POST /api/v2/query. Changing the URL is usually the entire migration — see §9 for the field-by-field mapping.

1.2What you get

One endpoint, every source

A single authenticated call fans out to breach databases, stealer-log collections, registry records and social platforms. You integrate once; new sources appear automatically.

Predictable billing

Credits are only consumed when a lookup returns data. Empty result sets on batch items, discovery calls and webhook test pings are always free.

Transparent limits

Per-key and per-IP rate limits are published up front and echoed on every discovery call, so your client can self-throttle instead of guessing.

Push, not poll

Register a monitor on any (type, value) pair and receive an HMAC-signed POST whenever the underlying result set changes.

Batch by design

Send up to 25 queries — uniform or mixed types — in one request. Failures are isolated per item so one bad target never kills the batch.

Stable contracts

v1 remains fully supported alongside v2. Response envelopes are additive-only: new fields may appear, existing ones never change meaning.

Quickstart

Go from a fresh account to a working lookup in four steps.

Four steps from zero to your first result. Total time: about two minutes.

Activate a paid plan

API access requires an active Basic, Starter, Professional or Enterprise subscription. Free accounts can browse the dashboard but receive 401 on every API call.

Generate an API key

Go to Dashboard → Settings → API Keys and click Generate New Key. The key is shown once — store it in your secret manager or environment, never in source control.

Verify your key

Call the discovery endpoint. It confirms the key works, reports your plan and rate limit, and lists every type your account can query — all without spending a credit.

bashfree — no credit consumed 
curl "https://eyegod.cc/api/v2/types" \
  -H "Authorization: Bearer YOUR_API_KEY"
Run your first lookup

Replace YOUR_API_KEY and run any of the following:

    headers={"Authorization": "Bearer YOUR_API_KEY"},

)
r.raise_for_status()
print(r.json()["found"], "records")
const res = await fetch(
  'https://eyegod.cc/api/v2/query/email/' + encodeURIComponent('foo@bar.com'),

03

Authentication

How to present your API key, where to store it, and how to rotate it safely.

Every endpoint requires a valid API key tied to an active paid plan. Keys are long-lived, scoped to a single account, and can be revoked instantly.

3.1Accepted methods

Bearer header Preferred
Authorization: Bearer <key>

Standard, works with every HTTP client and proxy. Use this unless you have a reason not to.

API key header Preferred
X-API-Key: <key>

Equivalent to Bearer. Handy when a gateway already reserves the Authorization header.

Request body Fallback
{"key": "<key>", ...}

For clients that cannot set custom headers. Functional, but headers are cleaner.

Never put a key in a query string?token= and ?key= are accepted for legacy compatibility, but query strings are written to server logs, proxy logs and browser history. Treat any key sent that way as compromised and rotate it.

3.2Key in the path v2

v2 accepts the key as the first path segment. The router detects that the segment is not a known lookup type and treats it as credentials. This makes the API usable from a browser address bar, a shell one-liner or a no-code tool that cannot set headers.

GET/api/v2/query/{key}/{type}/{value}no headers required
Convenience, not securityPath keys share the same exposure problem as query strings. Use them for local experiments and throwaway scripts — not for production traffic or anything that gets logged.

3.3A complete authenticated request

httprecommended form 
POST /api/v2/query HTTP/1.1
Host: eyegod.cc
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json

{"type":"ip","query":"8.8.8.8"}

Credits & billing

What consumes a credit, what does not, and how to keep an eye on your balance.

A credit is the unit of consumption. Your plan grants a monthly allowance; each successful lookup draws one credit. The remaining balance is returned on every response as credits_remaining.

4.1When a credit is charged

ScenarioChargedNotes
Lookup returns one or more records1 creditThe normal path. charged: true in the response.
Lookup returns zero records (v2)Freev2 does not bill empty result sets — charged: false.
Lookup returns zero records (v1)1 credithas_results: false still consumes a credit. One more reason to prefer v2.
Batch requestPer itemOnly items that return data are billed. See charged_total.
GET /api/v2/typesFreeDiscovery never touches an upstream source.
Webhook delivery1 creditCharged only when a check finds results and fires a delivery.
Webhook check with no resultsFreeSilent checks cost nothing.
Webhook test pingFreeSynthetic payload, no upstream call.
Cached resultFreeRepeat queries served from cache are not re-billed.
Rejected request (4xx)FreeAuth failures, unknown types and plan violations never bill.
You only pay for signalBecause empty v2 results are free, you can safely fan a target across many types to discover where exposure exists. Only the sources that actually return data draw down your balance.

4.3Monitoring your balance

Do not poll the discovery endpoint to watch your balance — read credits_remaining from the lookups you are already making and alert on a threshold.

pythonthreshold alerting 
LOW_WATERMARK = 50

def lookup(kind, value):
    payload = _request(kind, value)
    left = payload.get("credits_remaining")
    if isinstance(left, int) and left < LOW_WATERMARK:
        alert(f"EyeGod credits low: {left} remaining")
    return payload

Batch items count individuallyA batch of 25 queries consumes 25 slots against your per-minute budget, not one. Size your batches against the limit, not against the 25-item maximum.

5.1Third-party daily cap on Enterprise

Modules such as Reconly, Hudson Rock, Snusbase, Inf0sec and OsintCat are served by an upstream provider (stolen.tax) that we do not operate. That provider enforces a global quota of 1,000 requests per day shared across all EyeGod customers.

To stop one account from draining the shared pool, Enterprise keys are capped at 100 requests per day against these specific modules. Every other module — LeakSight, IP, OSINT, the social scrapers — remains unlimited.

5.3Recommended retry strategy

Retry on 429 and 5xx with exponential backoff and full jitter. Never retry 400, 401, 402 or 403 — those are deterministic and will fail identically every time. 

import time
import requests

def lookup_with_retry(session, url, attempts=5):
    """Exponential backoff that honours Retry-After."""
    delay = 1.0
    for attempt in range(attempts):
        r = session.get(url, timeout=30)

        if r.status_code == 429:
            wait = float(r.headers.get("Retry-After", delay))
            time.sleep(wait)
            delay = min(delay * 2, 60)
            continue

        if r.status_code >= 500:
            time.sleep(delay)
            delay = min(delay * 2, 60)
            continue

        r.raise_for_status()
        return r.json()

    raise RuntimeError(f"giving up after {attempts} attempts")
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

export async function lookupWithRetry(url, headers, attempts = 5) {
  let delay = 1000;
  for (let i = 0; i < attempts; i++) {
    const res = await fetch(url, { headers });

    if (res.status === 429) {
      const wait = Number(res.headers.get('retry-after')) * 1000 || delay;
      await sleep(wait);
      delay = Math.min(delay * 2, 60000);
      continue;
    }
    if (res.status >= 500) {
      await sleep(delay);
      delay = Math.min(delay * 2, 60000);
      continue;
    }
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return res.json();
  }
  throw new Error('rate limit retries exhausted');
}
Self-throttle before you get throttledRead rate_limit_per_min from the discovery endpoint at startup and pace your client below it. Reacting to 429 is a fallback, not a strategy.

Errors & status codes

Every status the API can return, what causes it, and whether retrying will help.

The API uses conventional HTTP status codes. 2xx means the request was processed, 4xx means something about your request needs fixing, and 5xx means the failure is on our side or an upstream provider's.

CodeMeaningTypical causeRetry?
200OKRequest succeeded. Inspect found / has_results — a valid query with no matches is still a 200.n/a
400Bad RequestMissing or malformed type / query, unknown type slug, or a value over 512 characters.No — fix the request
401UnauthorizedKey missing, malformed, revoked, or the account has no active paid plan.No — check credentials
402Payment RequiredCredit balance exhausted for the current period.No — top up
403ForbiddenAn Enterprise-only type was requested with a lower-tier key. No credit consumed.No — upgrade
429Too Many RequestsPer-key or per-IP rate limit exceeded.Yes — with backoff
503Service UnavailableAn upstream intelligence provider is down or timing out.Yes — with backoff

6.2Defensive client pattern

pythonmapping status codes to exceptions 
class EyegodError(Exception):
    """Base class for every API failure."""

class AuthError(EyegodError): ...        # 401 — bad or revoked key
class QuotaError(EyegodError): ...       # 402 — out of credits
class PlanError(EyegodError): ...        # 403 — tier too low
class RateLimited(EyegodError): ...      # 429 — slow down
class UpstreamDown(EyegodError): ...     # 503 — provider unavailable

FATAL = {400: EyegodError, 401: AuthError, 402: QuotaError, 403: PlanError}

def handle(response):
    status = response.status_code

    if status == 200:
        body = response.json()
        if not body.get("ok", True):
            raise EyegodError(body.get("error", "unknown error"))
        return body

    if status in FATAL:
        raise FATAL[status](response.text)
    if status == 429:
        raise RateLimited(response.headers.get("Retry-After", "60"))
    if status >= 500:
        raise UpstreamDown(f"HTTP {status}")

    raise EyegodError(f"unexpected status {status}")

v2 — REST lookup Stable

The recommended interface. Type and value live in the URL path; POST is supported for parity with v1.

v2 puts the lookup type and the target value directly in the URL path. The same endpoint also accepts a POST body, so one integration covers browser calls, shell scripts and server-side batch jobs.

GET/api/v2/query/{type}/{value}single lookup

7.1Path parameters

ParameterRequiredDescription
typeRequiredA lookup type slug — see §10. Call GET /api/v2/types for the live list your key can access.
valueRequiredThe string to search for. Maximum 512 characters. URL-encode any /, ?, #, @ or space.
Always URL-encode the valueAn unencoded @ or / will silently split your path into the wrong segments. Use encodeURIComponent() in JS, urllib.parse.quote(value, safe="") in Python.

Batch requests

Process up to 25 targets in a single call, with per-item billing and per-item error isolation.

Batching amortizes connection overhead and keeps your job logic simple. Send up to 25 queries per request, either all of the same type or a mix.

POST/api/v2/queryup to 25 items
Billing and limits inside a batchOne credit is consumed per item that returns results — empty items are free. Each item also consumes one slot against your per-minute rate limit, so a 25-item batch costs 25 slots.

8.1Uniform batch — one type, many values

bash 
curl -X POST "https://eyegod.cc/api/v2/query" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"type":"url","queries":["google.com","facebook.com","github.com"]}'

8.2Mixed batch — different types per item

bash

        {"type":"url",   "query":"google.com"},
        {"type":"ip",    "query":"8.8.8.8"},
        {"type":"email", "query":"foo@bar.com"}

8.4Chunking a large target list

pythonsafe chunking with per-item error handling 
import itertools
import requests

API = "https://eyegod.cc/api/v2/query"
HEADERS = {"Authorization": "Bearer YOUR_API_KEY",
           "Content-Type": "application/json"}
CHUNK = 25          # hard maximum per request

def chunks(seq, size):
    it = iter(seq)
    while (block := list(itertools.islice(it, size))):
        yield block

def bulk_lookup(kind, values):
    """Yield every result across an arbitrarily long input list."""
    for block in chunks(values, CHUNK):
        r = requests.post(API, headers=HEADERS,
                          json={"type": kind, "queries": block}, timeout=90)
        r.raise_for_status()
        payload = r.json()

        for item in payload["results"]:
            if not item.get("ok"):
                print("failed:", item.get("query"), item.get("error"))
                continue
            yield item

        # Pace against the per-minute limit before the next chunk
        if payload.get("credits_remaining", 1) <= 0:
            raise SystemExit("out of credits")

hits = [i for i in bulk_lookup("url", ["a.com", "b.com", "c.com"]) if i["found"]]
print(f"{len(hits)} targets with exposure")

9.3Bootstrapping a client

javascriptcapability-aware, self-throttling client 
class EyegodClient {
  #key; #types = new Map(); #minInterval = 0; #lastCall = 0;

  constructor(key) { this.#key = key; }

  /** Fetch capabilities once, then self-throttle from the reported limit. */
  async bootstrap() {
    const res = await fetch('https://eyegod.cc/api/v2/types', {
      headers: { Authorization: `Bearer ${this.#key}` },
    });
    if (!res.ok) throw new Error(`bootstrap failed: HTTP ${res.status}`);

    const meta = await res.json();
    if (meta.rate_limit_per_min === 0) throw new Error('plan has no API access');

    for (const t of meta.types) this.#types.set(t.type, t);
    this.#minInterval = meta.rate_limit_per_min
      ? 60000 / meta.rate_limit_per_min
      : 0;

    return meta;
  }

  supports(type) {
    const t = this.#types.get(type);
    return Boolean(t && t.enabled);
  }

  async #pace() {
    const wait = this.#minInterval - (Date.now() - this.#lastCall);
    if (wait > 0) await new Promise((r) => setTimeout(r, wait));
    this.#lastCall = Date.now();
  }

  async query(type, value) {
    if (!this.supports(type)) throw new Error(`type unavailable: ${type}`);
    await this.#pace();
    const url = `https://eyegod.cc/api/v2/query/${type}/${encodeURIComponent(value)}`;
    const res = await fetch(url, { headers: { Authorization: `Bearer ${this.#key}` } });
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return res.json();
  }
}

10.4Verifying the signature

Always verify before you trustCompute the HMAC over the raw request body, before any JSON parsing. Parsing first and re-serializing will change the bytes and the signature will never match.
const crypto = require('crypto');

app.post('/webhooks/eyegod',
  express.raw({ type: 'application/json' }),   // raw body, not parsed
  (req, res) => {
    const sig = req.headers['x-eyegod-signature'] || '';
    const expected = 'sha256=' + crypto
      .createHmac('sha256', process.env.WEBHOOK_SECRET)
      .update(req.body)
      .digest('hex');

    const a = Buffer.from(sig);
    const b = Buffer.from(expected);
    if (a.length !== b.length || !crypto.timingSafeEqual(a, b)) {
      return res.sendStatus(401);
    }

    const payload = JSON.parse(req.body.toString());
    console.log('New exposure for', payload.query);

  });

from typing import Any

def records(payload: dict[str, Any]) -> list[dict]:
    """Extract records from either API version, without assuming a shape."""
    if not payload.get("ok", True):
        raise ValueError(payload.get("error", "request failed"))

    # v2 — normalized list is authoritative
    if "result" in payload:
        return payload.get("result") or []

    # v1 — fall back to the raw object
    if payload.get("has_results"):
        raw = payload.get("data") or {}
        return [raw] if isinstance(raw, dict) else list(raw)

    return []


def credits_left(payload: dict[str, Any]) -> int | None:
    """Never assume the field exists — providers can omit it on edge paths."""
    value = payload.get("credits_remaining")
    return value if isinstance(value, int) else None

"""Minimal EyeGod client — no dependencies beyond requests."""
import os
import time
from urllib.parse import quote

import requests

BASE = "https://eyegod.cc/api/v2"


class Eyegod:
    def __init__(self, key: str | None = None, timeout: int = 30):
        self.key = key or os.environ["EYEGOD_API_KEY"]
        self.timeout = timeout
        self.session = requests.Session()
        self.session.headers.update({
            "Authorization": f"Bearer {self.key}",
            "Content-Type": "application/json",
            "User-Agent": "my-app/1.0",
        })

    def query(self, kind: str, value: str) -> dict:
        """Single lookup. Returns the parsed envelope."""
        url = f"{BASE}/query/{kind}/{quote(value, safe='')}"
        return self._send("GET", url)

    def batch(self, kind: str, values: list[str]) -> dict:
        """Uniform batch — maximum 25 values per call."""
        if len(values) > 25:
            raise ValueError("batch limit is 25 items")
        return self._send("POST", f"{BASE}/query",
                          json={"type": kind, "queries": values})

    def types(self) -> dict:
        """Free capability probe."""
        return self._send("GET", f"{BASE}/types")

    def _send(self, method: str, url: str, **kw) -> dict:
        delay = 1.0
        for _ in range(5):
            r = self.session.request(method, url, timeout=self.timeout, **kw)

            if r.status_code == 429 or r.status_code >= 500:
                time.sleep(float(r.headers.get("Retry-After", delay)))
                delay = min(delay * 2, 60)
                continue

            r.raise_for_status()
            body = r.json()
            if not body.get("ok", True):
                raise RuntimeError(body.get("error", "request failed"))
            return body

        raise RuntimeError("retries exhausted")

// eyegod.mjs — zero-dependency client for Node 18+
const BASE = 'https://eyegod.cc/api/v2';

export class Eyegod {
  constructor(key = process.env.EYEGOD_API_KEY, { timeout = 30000 } = {}) {
    if (!key) throw new Error('EYEGOD_API_KEY is not set');
    this.key = key;
    this.timeout = timeout;
  }

  get #headers() {
    return {
      Authorization: `Bearer ${this.key}`,
      'Content-Type': 'application/json',
      'User-Agent': 'my-app/1.0',
    };
  }

  /** Single lookup. */
  query(type, value) {
    return this.#send(`${BASE}/query/${type}/${encodeURIComponent(value)}`);
  }

  /** Uniform batch — max 25 values. */
  batch(type, queries) {
    if (queries.length > 25) throw new Error('batch limit is 25 items');
    return this.#send(`${BASE}/query`, {
      method: 'POST',
      body: JSON.stringify({ type, queries }),
    });
  }

  /** Free capability probe. */
  types() {
    return this.#send(`${BASE}/types`);
  }

  async #send(url, init = {}, attempt = 0) {
    const ctrl = new AbortController();
    const timer = setTimeout(() => ctrl.abort(), this.timeout);

    try {
      const res = await fetch(url, {
        ...init,
        headers: this.#headers,
        signal: ctrl.signal,
      });

      if ((res.status === 429 || res.status >= 500) && attempt < 4) {
        const wait = Number(res.headers.get('retry-after')) * 1000
                  || 1000 * 2 ** attempt;
        await new Promise((r) => setTimeout(r, wait));
        return this.#send(url, init, attempt + 1);
      }

      if (!res.ok) throw new Error(`HTTP ${res.status}: ${await res.text()}`);

      const body = await res.json();
      if (body.ok === false) throw new Error(body.error ?? 'request failed');
      return body;
    } finally {
      clearTimeout(timer);
    }
  }
}

<?php
declare(strict_types=1);

final class Eyegod
{
    private const BASE = 'https://eyegod.cc/api/v2';

    public function __construct(
        private readonly string $key,
        private readonly int $timeout = 30,
    ) {}

    /** Single lookup. */
    public function query(string $type, string $value): array
    {
        $url = self::BASE . '/query/' . $type . '/' . rawurlencode($value);
        return $this->send($url);
    }

    /** Uniform batch — max 25 values. */
    public function batch(string $type, array $queries): array
    {
        if (count($queries) > 25) {
            throw new InvalidArgumentException('batch limit is 25 items');
        }
        return $this->send(
            self::BASE . '/query',
            json_encode(['type' => $type, 'queries' => $queries])
        );
    }

    private function send(string $url, ?string $body = null): array
    {
        $ch = curl_init($url);
        curl_setopt_array($ch, [
            CURLOPT_RETURNTRANSFER => true,
            CURLOPT_TIMEOUT        => $this->timeout,
            CURLOPT_HTTPHEADER     => [
                'Authorization: Bearer ' . $this->key,
                'Content-Type: application/json',
            ],
        ]);

        if ($body !== null) {
            curl_setopt($ch, CURLOPT_POST, true);
            curl_setopt($ch, CURLOPT_POSTFIELDS, $body);
        }

        $raw    = curl_exec($ch);
        $status = curl_getinfo($ch, CURLINFO_HTTP_CODE);
        curl_close($ch);

        if ($raw === false || $status >= 400) {
            throw new RuntimeException("EyeGod API error (HTTP {$status})");
        }

        return json_decode($raw, true, 512, JSON_THROW_ON_ERROR);
    }
}

		Key:  os.Getenv("EYEGOD_API_KEY"),
		HTTP: &http.Client{Timeout: 30 * time.Second},
	}
}

func (c *Client) Query(ctx context.Context, kind, value string) (*Response, error) {
	endpoint := fmt.Sprintf("%s/query/%s/%s", base, kind, url.PathEscape(value))

	req, err := http.NewRequestWithContext(ctx, http.MethodGet, endpoint, nil)
	if err != nil {
		return nil, err
	}
	req.Header.Set("Authorization", "Bearer "+c.Key)

	res, err := c.HTTP.Do(req)
	if err != nil {
		return nil, err
	}
	defer res.Body.Close()

	if res.StatusCode >= 400 {
		return nil, fmt.Errorf("eyegod: HTTP %d", res.StatusCode)
	}

	var out Response
	if err := json.NewDecoder(res.Body).Decode(&out); err != nil {
		return nil, err
	}
	if !out.OK {
		return nil, fmt.Errorf("eyegod: %s", out.Error)
	}
	return &out, nil
}

Best practices

Patterns that keep integrations fast, cheap and safe in production.

Rotate keys on a schedule

Issue one key per service and environment. Generate the replacement, deploy, then revoke the old one — both are valid during the overlap, so rotation is zero-downtime.

Throttle before you are throttled

Read rate_limit_per_min at startup and pace your client below it. Treat 429 as a bug in your pacing, not a normal control-flow signal.

Batch instead of looping

Twenty-five single calls and one 25-item batch cost the same credits, but the batch makes one connection and returns one envelope. Chunk long lists and process the results as a stream.

Cache aggressively

Breach data does not change by the second. Cache by (type, value) with a TTL measured in hours and you will cut credit burn dramatically.

Monitor, do not poll

If you need to know when something changes, register a webhook. A 15-minute poll loop burns 96 credits a day per target; a monitor only charges when there is actually news.

Log the envelope, not the payload

Store type, query, found, charged and credits_remaining. Retaining full result payloads in your own logs recreates the exposure you are investigating.
